## Experiment 2: disable native network response capture on the default browsing path — SUCCESS

Hypothesis: native IPC network capture was always enabled. For every request it captured request headers/body previews, response headers, and installed a `CefResponseFilter` that copied response bytes into an in-memory string up to 1MiB per request. This is valuable for diagnostics/replay but inappropriate on the normal browsing/benchmark fast path, especially for resource-heavy pages.

Change:
- Add `NativeNetworkCaptureEnabled()`.
- Default network capture off.
- Enable diagnostics with `VIMBROWSER_NETWORK_CAPTURE=1` or `--enable-vimbrowser-network-capture`.
- Keep returning the resource handler so native content blocking still runs.
- With capture disabled, no network records are created and no response filter is installed.

## Experiment 8: lazy-load restored background tabs for large sessions — SUCCESS

Common browser behavior is to restore tab shells and load background tabs on first activation.

Change:
- Add `Tab::deferred_load`.
- When restoring at least 8 startup tabs, create non-active restored tabs as `about:blank` browser views while preserving their intended URL in `Tab::url` for sidebar/state.
- Ignore the initial `about:blank` load start for deferred tabs so it does not overwrite the stored URL.
- On first activation in `ApplyActiveBrowserSelection()`, clear `deferred_load` and load the preserved URL.
- Newly opened tabs and small sessions remain eager; the existing deterministic local restore benchmark with 6 tabs is intentionally unaffected.
